# CONTRIBUTING / WORK STYLE

## Before coding

Explain the current task and the smallest implementation path.

## During coding

Keep commits/changes focused where practical.

Do not mix:
- major architecture changes
- UI redesign
- unrelated refactoring

## After coding

Report:

```text
Implemented:
- ...

Files changed:
- ...

Run:
- ...

Tests:
- ...

Known limitations:
- ...

Next recommended step:
- ...
```

## If blocked

Prefer:

1. simpler implementation
2. mock/local substitute
3. documented limitation

over introducing a large new subsystem.
